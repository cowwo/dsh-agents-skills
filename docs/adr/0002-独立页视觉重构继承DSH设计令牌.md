# 0002 · 独立页视觉重构：继承 DSH 设计令牌，零构建不变

- 状态：已采纳（执行方式见「待定」一节）
- 日期：2026-10-13
- 相关文件：`lib/page.js`、`client/page-ui.js`、`test/page.test.mjs`、`prototype/standalone-refactor.html`
- 关联：[0001 · 独立页交互层允许少量 JS](./0001-独立页交互层允许少量JS.md)

## 背景（Context）

独立页 `/dsh-agents-skills` 现在的样式是 `lib/page.js:148-289` 里一段自研 CSS：一套自命名的变量
（`--paper` `--ink` `--sub` `--line` `--amber` `--ok` `--err`），设计语言自称「运维台账风」，
靠 `@media (prefers-color-scheme: dark)` 跟随**操作系统**深浅色。

用户反馈三类问题：①信息密度差、排版像半成品；②配色廉价、与 DSH 不像一套东西；③操作路径长、
反馈缺失（点了没动静）、缺批量快捷操作。

同时有三个硬事实约束着改法：

1. 插件**零构建**（无 `scripts`、无打包器、无 dist），Client 半是现成 JS 直接交付。
2. 独立页 CSP 只允许**一个同源外链脚本**，**禁止内联脚本**（0001 的底线）。
3. `test/page.test.mjs`（1383 行）是纯字符串断言，逐字锁定了旧 CSS 正文、旧 class 名与表头列序，
   它是唯一的验收裁判。

## 决策（Decision）

### 一、配色改吃 DSH 设计令牌，不再自命名颜色

界面颜色、圆角、字体、过渡时长一律引用宿主的 `--dsw-alias-*` / `--dsw-radius-*` /
`--dsw-font-family` 令牌；自有样式里**不写死任何色值**（原型自检脚本把这条做成了硬断言）。
收益：与 DSH 天然同族；宿主换主题、换品牌时不需要改插件。

代价（必须记录）：独立页是 Host 半的 SSR，**页面里没有宿主的样式表**，令牌必须由插件自己带一份
（从 `dsh-client-ui-theme` 提取的 token 段，当前约 19 KB）。也就是说「继承令牌」= 复制令牌定义，
**不是**运行时共享。宿主升级令牌值时，这份副本需要重新提取。

### 二、亮/暗跟 DSH 的实际主题，而不是操作系统

旧行为是 `prefers-color-scheme`，会出现「DSH 设置成亮色、但操作系统是深色 → 独立页变暗」的不一致。
新行为以 DSH 的选择为准，切换选择器沿用宿主自己的 `body[data-ds-dark-theme]`。

### 三、不动渲染模型与协议

- 保留 SSR + 表单/链接，**协议值一个字不改**（`row` / `batch` / `pick` / `subscribe` / `check` / `tab` …）。
- 保留左栏导航（不改成顶部标签、不做主从分栏）。
- 保留**表格**这一信息骨架（不改成卡片流），因为整页 69 行技能、8 列数据，表格是密度最高的载体。
- `client/page-ui.js` 只做必要的适配性修改，不新增第二个脚本、不引入内联脚本、不引入依赖、不新增构建步骤。

### 四、交互「人性化」的验收面（本次必须落地的东西）

| 项 | 旧状 | 新要求 |
|---|---|---|
| 搜索/筛选 | 折叠区里的搜索安装；「仅显示待办」是提交式 | 顶部工具条常驻，按名字实时筛选 + 状态 chip 一键收窄 |
| 批量操作 | 有批量条但发现性差 | 勾选任意行即浮出批量条（含选中计数），表头支持全选/半选 |
| 反馈 | 整页 303 回跳，无 busy、无 toast | 提交按钮进入「检查中…」态；操作结果就地提示；空态有文案 |
| 长列表 | 69 行一次铺开 | 默认只展开**有待办**的仓库，其余折起并显示计数 |
| 状态可读性 | 徽章与文本混排、部分说明列是 frontmatter 残渣 | 状态统一四种徽标（已装/新增/可更新/上游已移除），说明列修掉残渣 |

## 约束（Constraints）

- 零构建、无依赖、无内联脚本（CSP 底线不动）。
- 独立页操作在**关闭 JS** 时仍全部可用（表单/链接兜底不能少）。
- `test/page.test.mjs` 的**逐字结构断言允许随新结构更新**，但行为类断言（门禁 fail-closed、
  分组一致性、HTML 转义、pjax、cookie 记标签、CSP 指令集合）必须保留。
- 本轮只改独立页；设置页 `client/client.js` 与它的 React 面板**不动**。

## 后果（Consequences）

- 一次性成本：token 副本需要随 DSH 版本重新提取（记为维护项）。
- `test/page.test.mjs` 中大量「逐字 CSS 文本」断言会随重构失效，需要重写为**语义断言**
  （断言存在某个 class 的使用、断言可见文案），否则每次调样式都要改测试。
- 旧 class 名（`repo-name` `skill-name` `badge ok/warn/err` `batchbar` `repostrip` `fold` …）
  若继续沿用，可显著减少测试重写量；若重命名，需要同步改测试与 pjax 的选择器。
- 用户可见回归风险集中在：粘性表头偏移（README 记过「写 38px 会盖住第一行」）、
  窄屏 720px 断点行为、POST 后滚动位置保持。

## 待定（Open）

- **主题传递机制**：SSR 页面如何得知 DSH 的明暗选择（服务端设置存储 vs 由 `page-ui.js` 读浏览器侧）。
  约束：必须在「只允许一个同源外链脚本」下成立。方案确定后补写进本 ADR。
